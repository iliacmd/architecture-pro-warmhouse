# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

- Клиенты могут заказать установку системы отопления с подключением к системе

**Управление отоплением:**

- Пользователи могут выставлять температуру в комнате
- Пользователи могут вкл./выкл. отопление в комнате
- Система поддерживает регистрацию нового датчика (при его подключении)
- Система поддерживает удаление существующего датчика (при его отключении)
- Система поддерживает включение и выключение датчика
- Система поддерживает установку значения датчика

**Мониторинг температуры:**

- Пользователи могут узнавать температуру в заданной комнате
- Система поддерживает получение температуры с датчика

### 2. Анализ архитектуры монолитного приложения

Система реализована в виде приложения на языке Go, для хранения данных о датчиках используется реляционная СУБД PostgreSQL.
Для взаимодействия с системой реализован RESTfull API. 
Система получает данные датчиков посредством выполнения запроса по HTTP к датчику.
Система состоит из компонентов SensorHandler, DB, TemperatureService

# Задание 3. Разработка ER-диаграммы

Добавьте сюда ER-диаграмму.
Она должна отражать ключевые сущности системы, их атрибуты и тип связей между ними.

### Device Service
Device (Устройство)
id — SERIAL, первичный ключ
device_type_id — SERIAL, внешний ключ к DeviceType
name — строка (например, "Датчик температуры в гостиной")
status — enum('online', 'offline', 'error', 'updating')
location — строка (комната/место установки)
connection_status enum('connected', 'disconnected')
connection_info — JSONB (протокол, endpoint, credentials)
configuration — JSONB (специфичные настройки устройства)
created_at — TIMESTAMP
updated_at — TIMESTAMP

DeviceType (Тип устройства)
id — SERIAL, первичный ключ
name — строка (например, "Термостат", "Датчик движения")
capabilities — JSONB (поддерживаемые команды и метрики)
protocol_type VARCHAR(50) — строка (например, "MQTT", "Zigbee", "HTTP")
schema — JSONB (схема конфигурации и телеметрии)

### Telemetry Service
TelemetryData (Данные телеметрии)
id — SERIAL, первичный ключ
device_id — SERIAL, внешний ключ к Device
telemetry_type_id — SERIAL внешний ключ к TelemetryType
value — JSONB(например, "temperature": 22.5, "humidity": 45)
timestamp — TIMESTAMP

TelemetryType
id — SERIAL, первичный ключ
name VARCHAR(100) -- 'temperature', 'humidity', 'power_consumption'
data_type ENUM('number', 'boolean', 'string', 'json')
unit VARCHAR(20) -- 'celsius', 'percent', 'watt'
range_min DECIMAL(10, 4)
range_max DECIMAL(10, 4)

### User Service
User (Пользователь)
id — SERIAL, первичный ключ
email — строка, уникальный
password_hash — строка
first_name — строка
last_name — строка
created_at — временная метка
updated_at — временная метка
status — enum (active, inactive, suspended)

**Пользователь — Устройство**: один-ко-многим (один пользователь может владеть несколькими устройствами)
**Устройство — Тип устройства**: многие-к-одному (устройство относится к одному типу)
**Устройство — Телеметрия**: один-ко-многим (устройство генерирует много записей телеметрии)
